# React · Un panier persistant et compréhensible

**Atelier 02/06 · 4 h 30 · nr-02-cart**

Une personne choisit quelques produits, corrige les quantités puis recharge la page. Elle doit retrouver son intention sans prendre un ancien prix local pour une promesse de réservation. Le panier reste utilisable même lorsqu’une relecture du catalogue échoue.

Ce dépôt contient les instructions, les mémos et les espaces de travail. **Le code est à construire ; aucune solution terminée n’est fournie dans le dépôt élève.** Les acquisitions précédentes sont reprises avant la séance selon [Day 0](DAY0.md).

## À la fin de la séance

- Modéliser les transitions du panier avec des invariants explicites.
- Restaurer un état navigateur après validation et relecture serveur.
- Expliquer la différence entre total estimé et montant confirmé.
- Tester le rechargement, la corruption du stockage et le clavier.

## Déroulé de 270 minutes

| Séquence | Minutes |
| --- | --- |
| Actions et invariants | 20 |
| Transitions du panier | 45 |
| Composants et contrôles | 65 |
| Persistance et relecture | 55 |
| Tests et incidents | 60 |
| Revue et remise | 25 |

Répartition cible de cette séance : **240 min frontend / 30 min backend**, tests et revue de chaque couche inclus. Sur le cursus : **18 h frontend et 9 h backend**. Cette dominante React est un choix pédagogique, pas un ratio chiffré attribué à l’annonce.
